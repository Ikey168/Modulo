# Server-side service adapters

Issue: [#495](https://github.com/Ikey168/Modulo/issues/495). Code:
`backend/src/main/java/com/modulo/remote/`, client `frontend/src/platform/network.ts`.

The desktop shell runs feed sync, web capture, web watches, CalDAV, ntfy,
metadata lookups and PDF tools locally. Android and browsers cannot, so the
Modulo server offers the same operations under `/api/remote` (authenticated,
owner-scoped). `networkServices()` returns the desktop services in Electron and
the server client everywhere else; results have the same shape, so plugin
records do not depend on where an operation ran.

| Endpoint | Replaces | Notes |
| --- | --- | --- |
| `POST /api/remote/feeds` | `feeds.sync` | RSS/Atom, or Miniflux with the saved `minifluxToken` |
| `POST /api/remote/archive/capture` | `archive.capture` | Page saved as a workspace file (`fileId`), downloadable from any device; HTML is never served inline |
| `POST /api/remote/archive/import` | `archive.import` | Karakeep (with `karakeepToken`) or ArchiveBox JSON |
| `POST /api/remote/web-watch/check` | `webWatch.check` | Stateless: the record's last hash and snapshot go in, the next state comes out (up to 25 per call) |
| `POST /api/remote/caldav` | `caldav.sync` | CalDAV `REPORT` or a plain `.ics` URL, with the saved CalDAV credentials |
| `POST /api/remote/ntfy` | `ntfy.publish` | Optional `ntfyToken` |
| `GET /api/remote/metadata` | `providers.search` | Open Library, MusicBrainz, TMDB, YouTube, IGDB |
| `POST /api/remote/pdf` | `pdf.run` | Merge, split (ZIP of pages), rotate, extract text; 20 files, 25 MB each, 2,000 pages; encrypted PDFs refused; nothing is stored |
| `GET/PUT /api/remote/credentials` | `credentials.status/set` | Write-only; a blank value deletes |

## Outbound request policy

Every URL comes from a user, so `SafeHttpFetcher` treats each request as a
potential server-side request forgery:

- only `http`/`https` (`webcal` is read as `https`) on ports 80, 443, 8080 and
  8443, and no user name or password in the URL;
- every connection, including each redirect hop, resolves through a DNS
  resolver that refuses loopback, private, link-local (including cloud
  metadata at 169.254.169.254), carrier-grade NAT, unique-local, multicast and
  unspecified addresses, and IPv4 addresses embedded in IPv6. Checking at
  connect time closes the DNS-rebinding gap between a check and the request;
- no system proxy, at most 5 redirects to http/https only, 10 s timeouts,
  responses capped at 5 MB, no cookies.

Self-hosted services on the server's own network (Miniflux, Radicale, ntfy on
the LAN) are refused by default. An administrator can allow them with
`MODULO_REMOTE_ALLOW_PRIVATE_NETWORKS=true`, which lets any signed-in user make
the server request internal addresses; enable it only on single-user or
trusted deployments. The desktop app continues to reach home-network services
directly.

## Credentials

Provider tokens are stored per user in `remote_service_credentials`, AES-GCM
encrypted with `MODULO_REMOTE_CREDENTIAL_KEY` (32 bytes, base64; generated by
`deploy/oci/init-env.sh`). The owner id and key name are authenticated data, so
a ciphertext cannot be moved to another user or key. The API reports which
keys are configured and never returns values. Without the key, saving a
credential answers `REMOTE_CREDENTIALS_UNCONFIGURED` and the client explains
what the administrator must set. Browsers keep their session-only metadata
credentials; only IGDB, whose token exchange browsers cannot make, uses the
server.

## Errors

Failures return `{ "code": "..." }` with a stable code (`URL_ADDRESS_NOT_ALLOWED`,
`REMOTE_AUTH_REJECTED`, `CREDENTIAL_MISSING_CALDAV`, `PDF_ENCRYPTED`, ...);
`network.ts` turns each into a sentence that says what to do. Upstream bodies
and stack traces are never relayed.

## Remaining gaps

These stay capability gaps with a documented alternative, tracked on #495:

| Capability | Alternative on Android and web |
| --- | --- |
| `device.folders` (Managed Files indexing a local folder) | Pick files with the system picker; they become server attachments |
| `documents.ocr` (Tesseract OCR) | Document Inbox imports files and extracts embedded text; image OCR runs in the desktop app |
| `backup.archive` (ZIP with attachments, folder sync) | JSON backup, saved or shared through the system dialog |
| Background web-watch schedule | Off the desktop, watches are checked when the user opens Web Watch or taps Check; there is no server-side schedule yet |
